## Original requirements and acceptance criteria from GitHub issue #159

## Problem and observed evidence
Summa uses `--ef-color-action-primary`, `--ef-color-text-link`, `--ef-color-focus`, and `--ef-color-text-danger` with hard-coded CSS fallbacks, although those names are absent from Forma 0.6.1's exported core semantic token definitions. Consumers can therefore appear to follow Forma while silently selecting independent colors. See [Summa source](https://github.com/kemiller2002/summa/blob/main/app/summa-app.css) and [Forma tokens](https://github.com/kemiller2002/forma/blob/main/tokens/echelon.tokens.json).

## Requirements
- **FORMA-COLOR-001.1:** Publish a versioned, generated and consumable manifest of *public* semantic CSS properties for each released theme/brand, including name, role, applicable scopes, supported theme variants, source/provenance and deprecated aliases. Separate public tokens from internal implementation variables.
- **FORMA-COLOR-001.2:** Provide a deterministic validation API/CLI usable by application and Dokimos CI to identify unknown `var(--ef-*)` references, distinguish unsupported names from legitimate application-local variables, and report file/line and suggested supported role.
- **FORMA-COLOR-001.3:** Explicitly specify whether literal fallbacks are permitted for public tokens. A fallback MUST NOT silently substitute an unapproved brand or semantic color for an unknown token. Report exceptions with a documented use case; generated styling must not rely on implicit guessed aliases.
- **FORMA-COLOR-001.4:** Make token/compiler outputs deterministic, versioned and release-compatible; consuming a different Forma release must be validated against that release's contract, not an arbitrary branch tip.
- **FORMA-COLOR-001.5:** Document intended replacements for Summa's currently unresolved references, including primary action, link, focus and danger roles; do not simply bless those spelling variants without a semantic decision.

## Acceptance criteria
- Automated fixtures reject the four actual Summa references against the current Forma 0.6.1 contract, but accept supported variables; a negative case verifies no false positive for a legitimate application-owned `--summa-*` variable.
- A consumer can run validation without copying or redefining Forma component CSS.
- Contract changes require versioned release notes and tests; diagnostics are actionable and reproducible.
- Document the distinction between **valid token use** and **appropriate palette selection**: this issue guarantees the former only.
