## Requirements

**RLP-002.1:** Determine whether the RLP-001 relational layout vocabulary compiles into deterministic, zero-runtime HTML and CSS. The compiled form must keep the correctness and the reduced decision count found in RLP-001, and should approach conventional CSS in visual quality.

**RLP-002.2:** Record the exact baseline before implementation (`experiments/RLP-002/BASELINE.md`): source commits, tool versions, assumptions and limitations. Never modify RLP-001 data. Never reconstruct missing RLP-001 data from its report.

**RLP-002.3:** Pre-register hypotheses H1–H6 before collecting confirmatory data, together with:
- endpoints, comparison rules and statistical methods;
- exclusion criteria and stop conditions.

Official records go in `research/experiments/`; the workbench is `experiments/RLP-002/`.

**RLP-002.4:** Keep the arms distinct:
- A, B and C are archived RLP-001 references, never described as concurrent controls.
- E compiles the relational vocabulary to static CSS with no visual change.
- F uses the same compiler with a separately versioned visual refinement ruleset.
- Arm D (physics) is neither rerun nor developed further.

**RLP-002.5:** Build a deterministic build-time compiler covering:
- containment, clearance, sibling separation, grouping and alignment;
- reading order, flexible rows, responsive reflow and intrinsic media;
- target size, overflow and stable dynamic behavior.

The delivered page must need no runtime JavaScript or WASM layout. Use F# where existing infrastructure justifies it. Do not use absolute positioning, attraction, repulsion, springs, gradient descent, energy minimization, or spacing derived from nesting depth.

**RLP-002.6:** Keep three concerns separate: hard constraints, semantic preferences and visual presentation. A relationship that CSS cannot express is recorded as unsupported, with a reproducible fixture. It is never silently approximated.

**RLP-002.7:** Stage 1: compile the preserved RLP-001 Arm C pages through Arm E, and compare invariants under the RLP-001 conditions. These are viewports 320, 375, 768, 1024 and 1440, held-out text, 200% font, dynamic steps and axe. The Stage 1 gate allows one focused correction cycle. If the gate still fails, stop before Stage 2 with evidence.

**RLP-002.8:** Arm F refinements:
- root gutters;
- intrinsic media;
- keep-together and wrap-tail rows;
- visual hierarchy;
- stable token spacing;
- responsive composition.

**RLP-002.9:** Blind visual evaluation puts reference and candidate pages in the same randomized design. It records criterion scores and defect labels, and keeps all ratings, mappings and analysis code.

**RLP-002.10:** Stage 2, only if Stage 1 passes:
- six held-out tasks × arms E and F × 3 repetitions;
- isolated workers, a fixed model and prompt, and identical validation budgets;
- recorded tokens, repairs, artifacts and decisions;
- a small concurrent Arm C control, subject to a recorded budget decision.

**RLP-002.11:** Statistics:
- task-paired analysis with uncertainty;
- confirmatory comparisons kept separate from exploratory ones, with multiplicity correction;
- no equivalence claims without a pre-registered margin.

**RLP-002.12:** Production Forma and Folio stay unchanged. No GitHub Issues. No automatic merge. No fabricated results.

**RLP-002.13:** The final report recommends one of ADOPT, REFINE, LIMIT or ABANDON, with the evidence for it. Praxis records are updated and validated.
