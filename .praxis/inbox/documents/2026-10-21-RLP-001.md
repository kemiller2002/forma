## Background

RLP-001 asks whether user interfaces are easier for AI agents to build correctly when spacing, containment, alignment, and grouping come from one consistent system of relationships instead of independently assigned CSS properties. It compares four arms: conventional CSS (A), standardized Forma primitives (B), relational constraints resolved by deterministic rules (C), and the same relational constraints resolved by constrained energy minimization (D). The experiment must test that hypothesis, not assume it.

## Requirements

**RLP-001.1 (isolation):** All experimental code lives under `experiments/RLP-001/`. No production stylesheet, pattern, token, package export, or public API changes. The production package stays zero-runtime HTML and CSS.

**RLP-001.2 (relational model):** Provide a semantic layout vocabulary that expresses containment, grouping (proximity bonds), alignment (shared edges, equal width), minimum separation, preferred proximity, and responsive arrangement. Arms C and D consume the identical vocabulary and receive identical semantic information.

**RLP-001.3 (deterministic resolver, Arm C):** Resolve the relational model into geometry with deterministic rules and no optimization.

**RLP-001.4 (physics resolver, Arm D):** Resolve the same model through constrained energy minimization `E(L) = wb·Eb + ws·Es + wa·Ea + wg·Eg (+ wc·Ec if justified)`, with hard constraints for containment, non-overlap, reading order, minimum interactive target size, required alignment, and minimum clearance. Document the mathematical definitions.

**RLP-001.5 (determinism):** Identical inputs produce identical geometry within a documented tolerance. Record solver configuration, initial conditions, iteration count, convergence tolerance, termination condition, and final constraint violations.

**RLP-001.6 (failure handling):** Detect unsatisfiable constraints, non-convergence, oscillation, invalid dimensions, excessive computation, and numeric instability. Return structured diagnostics. Never silently accept invalid geometry.

**RLP-001.7 (rendering):** Render through ordinary browser layout and re-resolve when content or viewport changes. Do not animate ordinary layout.

**RLP-001.8 (benchmarks):** Twelve benchmark tasks (forms 2, cards and nested panels 2, dashboards 2, navigation 2, dynamic content 2, adversarial 2), defined by semantic and functional requirements only. Development tasks and held-out tasks are separated, and the solvers are frozen before held-out tasks run.

**RLP-001.9 (geometry validation):** Playwright checks on real browser geometry at 320, 375, 768, 1024, and 1440 px: containment, clearance, sibling separation, overlap, alignment tolerance, horizontal overflow, clipping, interactive target size, reading order, accessibility (axe), dynamic reflow, unexpected layout shift, and deterministic geometry. Each failure names task, arm, attempt, viewport, element or relationship, expected invariant, and observed result. Results are machine-readable.

**RLP-001.10 (dynamic content):** For each relevant task, measure after initial render, insertion, removal, text expansion, and validation messages.

**RLP-001.11 (agent efficiency instrumentation):** Record input, output, and total tokens where available, tool calls, repair iterations, duration, and successful and failed attempts. Distinguish zero from unavailable. Count the complete execution, including corrections and failures.

**RLP-001.12 (decision instrumentation):** A documented rubric classifies independent layout decisions (padding, margin, alignment, positioning, grouping, responsive behavior, dimension, manual correction) as explicit, framework-derived, corrective, or uncertain. A blinded independent review of a sample measures classification consistency.

**RLP-001.13 (pilot):** 3 tasks × 4 arms × 1 repetition. Gates: solver convergence, arm comparability, measurement reliability, objective evaluability, and no serious unresolved accessibility problem. Stop before the full experiment if a gate fails.

**RLP-001.14 (full experiment):** If the pilot passes, 12 tasks × 4 arms × 3 repetitions in randomized order, in isolated workspaces, with the same model, configuration, and budget per attempt.

**RLP-001.15 (blind visual evaluation):** Arm-anonymized, order-randomized screenshots scored by independent reviewers, with disagreements recorded.

**RLP-001.16 (analysis and report):** Per-arm descriptive statistics, paired per-task comparisons (A vs D primary; A vs B, B vs C, C vs D mechanisms), effect sizes, intervals where appropriate, cost per accepted interface, and decision-count analysis. Exploratory and confirmatory findings are labeled separately. Publish raw data, a failure analysis, reproduction instructions, and an evidence-backed recommendation (outcome A, B, C, or D).
