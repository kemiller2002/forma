# AI-discoverable Forma contracts and typed email expressions
Date: 2026-11-23. Proposed only.

Every public Forma input, component, property, event, state, composition and email-designer block must expose a versioned machine-readable assistant contract: intent, type, validation, dependencies, accessibility, permitted states, examples, errors, safe guidance and source references. Generate human docs, AI help and validation projections from one authoritative contract with reviewed semantic annotations. Preserve Forma zero-runtime: agent behavior and data/authorization belong to consuming apps.

Email designer: extend the existing versioned structured document with a **typed declarative expression layer**, not a second layout schema. Typed event-scoped placeholders, bounded conditionals/collections, formatters, protected fragments, static validation, deterministic HTML/plain-text/subject rendering, contextual encoding and AI discovery. Optional human-friendly syntax compiles into the canonical AST. No arbitrary code or data fetching. Document compatibility and migration; support synthetic previews and diagnostics.

Validate component inventory coverage and missing assistant metadata, schema drift, keyboard/mobile contextual help, untrusted text/prompt injection, and version pinning. Coordinate with Unbound specs AI-DISCOVERABLE-CONTRACTS-AND-SAFE-ASSISTANCE and TYPED-EMAIL-TEMPLATE-LANGUAGE-AND-AI-AUTHORING-ASSISTANCE. No implementation claimed.
